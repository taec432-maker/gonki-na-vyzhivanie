# Промпт для Opus 5.5 — Этап 0: Каркас

Скопируй всё, что ниже линии, в новую облачную сессию с репозиторием `taec432-maker/gonki-na-vyzhivanie`.

---

Ты работаешь в репозитории taec432-maker/gonki-na-vyzhivanie (ветка main). Заказчик — Александр, не программист, общение по-русски.

Сначала прочитай целиком ТЗ.md, CHANGELOG.md, docs/РЕШЕНИЯ.md (если есть) и этот промпт. Правила раздела 11 ТЗ обязательны: без заглушек, `npm run check` зелёный перед пушем, детерминизм по seed, бюджет 16 мс на кадр, свободные лицензии с записью в ASSETS.md, маленькие коммиты по-русски, пуш в main.

Если в ТЗ чего-то нет — выбери разумный вариант, запиши в docs/РЕШЕНИЯ.md и продолжай, не останавливайся с вопросами. Вопросы к заказчику — в конец отчёта.

В конце: обнови CHANGELOG.md (что сделано / что не вошло / «Как проверить» — по шагам для заказчика), положи 3–5 скриншотов в docs/screenshots/этап-0/, запушь и напиши заказчику короткий отчёт по-русски в том же формате.

Задача этапа 0 — каркас проекта (раздел 10 ТЗ, «Этап 0»).

1. Изучи референсы из раздела 13 ТЗ: клонируй https://github.com/szabolevi98/racing и примеры vehicle controller из rapier.js — прочитай, как у них устроены машина и трасса. Запиши в docs/РЕШЕНИЯ.md, что берёшь как идею и что пишешь своё (лицензии!).
2. Создай проект: Vite + TypeScript strict + three + @dimforge/rapier3d-compat + postprocessing; ESLint + Prettier; Vitest; Playwright (headless Chromium, флаги --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist). Скрипты: dev, build, check (tsc + eslint + vitest + playwright), check:ci (то же без playwright, если в CI нет GPU-эмуляции — проверь, swiftshader в GitHub Actions обычно работает). Сборка должна уважать переменную VITE_BASE (для GitHub Pages путь /gonki-na-vyzhivanie/), по умолчанию "/". Три страницы: / (игра), /control (панель), /overlay (прозрачный оверлей) — через multi-page Vite.
3. Структура src/ по разделу 4 ТЗ (пустые модули с index.ts — допустимо только на этом этапе; в CHANGELOG перечисли, какие пустые).
4. Игра: Rapier-мир с фиксированным шагом 60 Гц и интерполяцией рендера, seed-рандом (?seed=), плоская тестовая трасса-овал из сплайна (src/tracks/test-oval.json), одна машина на простом raycast-vehicle, которая сама едет по сплайну (простейший ИИ «держись линии»), камера за машиной, HDRI с Poly Haven (CC0) + ACES, HUD со скоростью и fps.
5. /control: статус, кнопки «Старт/Стоп/Рестарт», ползунок качества (пока меняет только разрешение рендера).
6. Playwright-smoke: открыть /?seed=42, дождаться старта, 10 с симуляции, три скриншота, нет ошибок в консоли, медианный frame time в лог (порог адаптивный — в SwiftShader медленно, важно отсутствие провалов и ошибок).
7. Проверь, что .github/workflows/pages.yml собирает и публикует проект (он уже лежит в репозитории — поправь под реальные скрипты), и что «Обновить и запустить.command» работает с твоим package.json (нужен `serve` через npx, build в dist/).
8. README.md — обнови раздел для разработки под реальные команды.

Готово, когда: заказчик дважды щёлкает «Обновить и запустить.command», видит едущую машину и fps; ссылка Pages открывается и показывает то же самое.
